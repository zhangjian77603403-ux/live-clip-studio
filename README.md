# Live Clip Studio

[![Sponsor](https://img.shields.io/badge/%E8%B5%9E%E5%8A%A9-%E7%88%B1%E5%8F%91%E7%94%B5-946ce6?style=flat-square)](https://ifdian.net/a/phoom)

本地模型驱动的口播带货短视频生产线：一个桌面工作台 + 一条可复现的生成流水线。
单主播、单场景、单商品，从商品图到带中文字幕的成片，全程不用手工剪辑。

> 这不是一个开箱即用的软件。它是一层**编排代码**，跑在你自己的 ComfyUI + 本地视频模型之上。
> 前置条件见下文，缺一样都跑不起来。

---

## 它解决什么问题

用通用视频模型做「同一个主播、同一个场景、连续讲 30~60 秒」的带货口播，最难的不是生成单条好看的片段，而是：

1. **人、场景、商品在 8 个镜头里保持一致**
2. **语速和镜头时长对得上**，不靠后期变速
3. **拼接处不跳、不黑帧、不吞字**

这个项目把三件事都做成了确定性流程，代价和取舍都写在代码注释里，没有魔法。

## 能做什么 / 不能做什么

| 能做 | 不能做 |
|---|---|
| 单主播坐播口播，480×854 / 24fps / 原生音频 | 多机位、多场景、剧情短片 |
| 商品固定：从一张商品图生成商品主视图 | 复杂手部操作、商品特写转场 |
| 8 个镜头，每镜 5~10 秒，整段直拼 | 精确到 0.1 秒的总时长（受模型帧数档位限制） |
| 自动出 SRT/ASS 字幕、-16 LUFS 响度标准化 | 自动识别商品瑕疵、自动审核内容合规 |

## 前置条件

| 依赖 | 要求 | 说明 |

| ComfyUI | 跑在 `http://127.0.0.1:8188`，也可用 `LCS_COMFY_URL` 覆盖 | 必须已加载下面两个模型 |

| 显卡 | 能跑 480P 视频推理 | 建议 ≥12 GB 显存 |

```bash
pip install -r requirements.txt
```

WebView2 Runtime：Win10/11 自带；Win7/8 需要 [手动安装](https://developer.microsoft.com/microsoft-edge/webview2/)。

## 快速开始

```bash
cp config.example.json config.json
python server.py          # 浏览器打开 http://127.0.0.1:8801
python app.py             # 或者用原生窗口（需要 pywebview）
```

`config.json` 里 `project_root` 留空时，默认在程序目录下建 `视频项目/`。

生产一个新片子：

```bash
# 1) 商品图 + 定妆照候选（跑多次挑一张）
python pipeline/run_stage.py --project "视频项目/01_保温杯_60秒" --stage assets

# 2) 八个镜头，每个镜头首帧=尾帧=同一张定妆照
python pipeline/run_stage.py --project "视频项目/01_保温杯_60秒" --stage shots

# 3) 直拼 + 字幕 + 响度标准化
python pipeline/run_stage.py --project "视频项目/01_保温杯_60秒" --stage final
```

工作台里就是这三个按钮（`① 出图` / `② 生成镜头` / `③ 合成成片`），外加「一键生成」串起 ②③。

---

## 三个阶段的原理

**① assets** — Z-Image 出商品主视图，再生成「主播坐桌前、商品摆桌上」的定妆照候选（多个 seed）。
人工挑一张定稿，后续八个镜头全部锁死这张图。

**② shots** — 每镜的 `first_frame` 和 `last_frame` **都是同一张定妆照**。
不用链式（上一镜尾帧做下一镜首帧）：实测链式会让画面噪声逐镜累积，S01→S08 墙面噪声涨 184%。

**③ final** — 按实测时长整段直拼，不 trim；字幕按 `silencedetect` 定位口播区间，再按字数比例分时间轴；最后 `loudnorm -16 LUFS / TP -1.5 dB`。

## 两条硬规则

这两条是整个项目里最值得抄的部分。

### 规则一：台词字数 = 分镜秒数 × 5

想让人每秒说 5 个字，就不能让模型自由发挥语速。做法是把字数写死：

```python
CPS = 5
want_chars = round(nominal_seconds * CPS)      # 5 秒镜 → 25 字
```

提示词里写成 `completes the exact sentence by (字数/5 - 0.15) 秒`。
多写会被拉快变糊，少写会被拖慢变拖沓，偏差超过 2 字脚本会报警。

### 规则二：剪辑不许删减，必须无缝对接

不生成「5.6 秒剪成 5.0 秒」，而是**先让帧数对齐**：

- H3 的合法帧数只能是 `5 + 17k`（124 / 141 / 158 / 175 / …），做不到正好 5.000 秒
- `snap_frames()` 取「装得下 名义时长 + 0.1 秒」的最小合法帧数 → 5 秒镜落到 124 帧 = 5.167 秒
- 每镜整段素材原样进拼接，切点落在说完之后，句尾留白也保留

代价很明确：6 镜 × 5 秒，成片是 31.0 秒不是 30.0 秒。想要精确 30 秒，只能改镜数或秒数配比。

## 项目目录约定

```
视频项目/01_保温杯_60秒/
├── 01_方案/           方案与分镜脚本
├── 02_生成源/
│   ├── raw/S01.mp4 …  每镜原始素材
│   ├── work/          中间产物、字幕
│   └── progress.json  进度（工作台据此判断按钮可用性）
├── 03_商品素材/       商品主视图（含 _历史/ 归档）
├── 04_分镜参考/       host_scene_ref.png 定妆照
├── 05_审核记录/       consistency_report.json、审核*.json
└── 11_成片/           最终 MP4
```

工作台靠「两位数字开头 + 含 `11_成片` 或 `02_生成源`」识别项目。

## 审核指标

工作台右侧九宫格直接读 `05_审核记录/` 下的 JSON，不额外算：

| 指标 | 绿色 | 橙色 | 红色 |
|---|---|---|---|
| F0 跨度（声线一致性） | ≤25% | 25–40% | >40% |
| 频谱质心跨度 | ≤25% | 25–45% | >45% |
| 响度 | -16 LUFS ±1 | ±2 | 超出 |

墙面平整区噪声（5×5 局部标准差）S01→S08 若递增，说明画面在逐镜劣化。

## 已知限制

- **声线不可控**：模型没有独立的说话人通道，声线是台词语域的副产品。台词风格突变会导致频谱质心漂移 200~400 Hz。
- **小配件会漂**：提环、挂绳、吸管这类细小配件在镜头间可能凭空长出来或消失。目前只能目视核查，两次自动检测尝试都失败（阈值窗口被商品边缘和头发污染）。
- **总时长不精确**：受帧数档位限制，见规则二。
- **单机单用户**：没有账号体系，服务只监听 `127.0.0.1`，设计上不对外网暴露。
